# CMS 001 Autenticación y configuración de inicio

## Entregado

Login por correo y contraseña, cierre de sesión, roles admin/editor en el backend, cuentas activas, cookies de sesión, protección CSRF y límite de intentos por IP. El panel incluye resumen y editor de nombre, portada, presentación, correo, teléfono, WhatsApp, dirección y horarios. La web pública carga estos campos desde MariaDB.

Cada publicación valida los campos en servidor, incrementa versión y registra auditoría en la misma transacción. Un conflicto de versión devuelve HTTP 409 sin sobrescribir cambios ajenos. La API devuelve HTTP 503 cuando falta configuración o hay un error de servicio, sin exponer credenciales ni trazas.

## Límites

No hay recuperación de contraseña, MFA ni gestión de cuentas desde la interfaz en esta entrega. Las cuentas iniciales se crean con consola. Los permisos se aplican para editar configuración; no se ha implementado aún un módulo de roles. Los demás módulos del menú están deshabilitados y marcados como pendientes. El editor publica directamente al guardar. Las imágenes siguen incluidas con la web, sin gestor de uploads. El formulario de contacto aún no envía ni guarda consultas.

## Endpoints

| Método | Ruta | Acceso |
| --- | --- | --- |
| GET | /api/public/settings | Público; solo campos públicos |
| GET | /api/admin/session | Usuario actual y token CSRF |
| POST | /api/admin/login | CSRF y límite de intentos |
| POST | /api/admin/logout | CSRF |
| GET | /api/admin/settings | Cuenta activa admin/editor |
| PUT | /api/admin/settings | Cuenta activa admin/editor, CSRF y versión vigente |

## Validación

Compilación de React/Vite aprobada. Pruebas de API contra MariaDB 10.11 y PHP 8.3 aprobadas: autenticación, cookie HttpOnly, sesión, acceso sin login, CSRF, validación de WhatsApp, persistencia pública, conflicto de versión y logout. Navegador Chromium: login, edición, publicación visible en portada, restauración del contenido y logout aprobados; sin excepciones JavaScript. Inspección visual del editor en escritorio y móvil y login móvil realizada.

Despliegue y validación específica de PHP 8.2 en el hosting pendientes.
